# 现代 RSS 阅读器改造计划

## 目标与边界

以 Fluent Reader 的本地数据、订阅和同步能力为基础，重新组织桌面阅读界面。先完成可操作的布局与真实订阅流程，再做视觉细节。目标分类是「全部、文章、社交、图片、视频」五个入口；用户文件夹与内容分类是两件事，不能把现有文件夹直接当成分类。全部和文章采用订阅栏、条目列表、阅读内容三栏；社交、图片、视频分别有适合内容形态的列表/卡片，点开后仍可阅读原文。

本轮只完成代码核对、真实数据探查、撤回前一版冲突界面和实施拆分。下面阶段按顺序交付，每阶段验证后再进入下一阶段。

## 对照 Folo 源码后确定的结构

- `D:\workspace\Folo\apps\desktop\layer\renderer\src\modules\app-layout\MainDestopLayout.tsx` 将订阅栏与主内容并列渲染。我们的桌面版订阅栏要常驻，占据实际布局宽度，不再沿用覆盖内容的菜单。
- `...\app-layout\subscription-column\SubscriptionColumn.tsx` 用拖动分隔器调整订阅栏宽度，源码范围为 256–300 px，并保存宽度。Folo 源码同时支持隐藏和临时展开；本项目按照需求选择桌面常驻，不照搬该行为。
- `...\modules\subscription-column\index.tsx` 的 `TabsRow` 是订阅栏顶部横向分类标签，标签下是当前分类的订阅和分组。主页加号在 `SubscriptionColumnHeader.tsx` 中是实际的操作按钮。
- `...\app-layout\ai-enhanced-timeline\AIEnhancedTimelineLayout.tsx` 的列表和阅读内容共用连续的主内容区域，以右边框和可拖动分隔器区分；不是两个分别加圆角的大卡片。条目列最小宽度为 300 px，并保存用户调整后的宽度。
- `...\modules\entry-column\Items\getItemComponentByView.ts` 将类型映射到不同条目组件。文章偏文字和小封面；社交显示发布者、正文与媒体；图片突出图片网格；视频突出 16:9 封面和视频信息。圆角只用于有独立边界的条目、媒体和按钮，由同一组设计变量控制；不对三个布局区块逐个套大圆角。
- Folo 的 `README.md` 明确指出 `icons/mgc` 图标不可再分发。阶段实现优先使用项目已有 Fluent UI 图标或许可明确的开源图标，不直接复制这批资源。

视觉验收以 Folo `README.md` 中的 Desktop 截图和对应源码为参照，在相同窗口尺寸下并排检查列宽、分隔线、条目密度、字号、留白、媒体比例和圆角层级。源码能说明布局关系，但不能替代运行后的截图；在完成首个界面阶段前，不宣称已达到 Folo 的视觉效果。

## Fluent Reader 现状与需要改动的接点

- `src/components/menu.tsx` 的订阅栏目前是固定定位的弹出菜单，`src/components/page.tsx` 和 `dist/styles/main.css` 又依据 `menu-on` 挪动正文。这是遮挡与三栏冲突的根源；要改成共同父级中的布局列，而不是继续调整边距。
- `src/components/settings/sources.tsx` 已有可用的 `addSource` 流程，但入口藏在设置页。主页加号应该打开明确的添加订阅表单；点击、输入、提交、错误与成功反馈都要在应用中验证。
- `src/schema-types.ts` 的 `ViewType` 是呈现样式（Cards/List/Magazine 等），不能直接当内容分类。`src/scripts/models/group.ts` 的 `SourceGroup` 是用户文件夹，也要保留原意。需要单独的五分类状态及每个订阅的类型。
- `src/scripts/db.ts` 的源表没有分类字段；条目表只有一个 `thumb`，缺少媒体列表、时长等字段。先定义老数据迁移策略，再实现分类与媒体解析；不能仅凭有无缩略图猜测图片或视频类别。
- `src/scripts/utils.ts` 从渲染进程直接 `fetch` RSS。当前本地 RSSHub 返回 `Access-Control-Allow-Origin: localhost:1200`，与应用 `file://` 页面的来源不匹配。需要在应用内复现并修复订阅读取路径，不能通过关闭浏览器安全机制掩盖问题。

## 真实订阅样本（2026-09-27，本地 `http://localhost:1200`）

| 类型 | RSSHub 路由 | 本次响应 | 样本特点与限制 |
| --- | --- | --- | --- |
| 文章 | `/juejin/category/frontend` | 200，20 条 | 有标题、作者和 HTML 正文；部分条目含图片。 |
| 社交候选 | `/weibo/search/hot` | 200，51 条 | 只有短热点标题，缺少作者与媒体；只适合检查基础订阅读取，不足以验收社交卡片。还需找到可访问的帖子流。 |
| 图片 | `/bing/` | 200，7 条 | 每条正文含图片，可验收封面提取和图片网格。 |
| 视频 | `/bilibili/ranking/0/3` | 200，100 条 | 有封面、作者和 enclosure；需检查是否有可用视频时长，缺失时不显示时长标记。 |

这些地址经过 XML 读取和本项目同配置的 `rss-parser` 解析。RSSHub 的上游可用性会变化，因此测试不能依赖固定条目数量；验收看应用中是否真的添加、读取和渲染当前数据。真实订阅在隔离的应用数据目录中测试，不写入用户当前资料。

## 交付顺序与每步验收

1. **连接与数据模型。** 验证 Electron 实际读取本地 RSSHub 的结果；修复必要的跨域读取路径。定义 `All/Articles/Social/Pictures/Videos`，给订阅增加持久化类别及老数据默认类别；「全部」聚合四类。解析图片与视频必要字段，保持旧库升级、OPML 与现有同步功能可用。用上述真实源逐一检查入库结果。
2. **桌面布局骨架。** 在共同的布局父级渲染常驻订阅栏和主内容区；订阅栏顶部横排五个标签，标签下保留用户分组。订阅栏及条目列可拖动，宽度持久化；分隔线有可见焦点和键盘可用性。设置页与窗口控制保持可操作。以窗口最小宽度 992 px、常用宽度 1200/1440 px、浅色/深色逐一检查没有遮挡或横向溢出。
3. **主页添加订阅。** 订阅栏加号打开表单，支持 URL、分类选择与错误反馈。用本地 RSSHub 完成一次实际添加，成功后新源出现在对应分类且可打开文章；重复 URL、无效 URL、RSSHub 失败都要有清楚反馈。
4. **全部与文章。** 共用三栏阅读结构，条目列表和阅读页之间只用分隔线/拖动条。确定统一的间距、字号、圆角变量后再做文章卡片、选中态、阅读排版和快捷键；同时检查空状态与长标题。
5. **社交。** 使用帖子时间线，展示发布者、正文、时间与多媒体；先找到内容足够完整的真实社交源，再按实际字段决定缺失信息的回退样式。
6. **图片。** 图片网格/瀑布流，以图片为主，支持打开条目和缺图回退；用 `/bing/` 验证真实图片加载、比例和滚动。
7. **视频。** 16:9 封面卡片，展示标题、作者及有数据时的时长；视频链接和原文打开行为明确，用 B 站样本验证。
8. **收尾。** 将状态信息移到与窗口按钮分离的位置，整理设置页的左右导航、隐私模式与快捷键；统一图标、亮暗主题与细节。逐项完成回归后再做整体视觉验收。

每阶段的最低检查：先 `npm install`，再 `npm run build`、`npx prettier --check .`；交互阶段还需应用内实际操作和对应宽度截图。当前仓库的私有 E2E 目录只有说明文件，若测试套件未安装，记录无法运行的原因，并用可重复的应用内步骤验证。所有阶段都应避免改动用户现有的 `.gitignore`、`package-lock.json` 和 `src/main/window.ts` 工作区修改；必要改动先核对其内容。

## 第一阶段实施记录

- RSS 读取改由 Electron 主进程发起，通过受限 IPC 返回字节数据给渲染进程解析；保留字符集检测，并限制请求协议、跳转协议与次数、超时和响应大小。隔离的 Electron 实例已从 `file://` 页面成功读取上表四条 RSSHub 路由；本地模拟服务还验证了正常跳转可用，跳转到 `file://`、循环跳转及超大响应被拒绝。
- 订阅库升至 v4，条目库升至 v2。订阅增加四种持久化内容类型，旧订阅默认归入文章；条目增加保存图片列表与视频信息的 `media` 字段，旧条目默认 `{}`。旧备份恢复和 OPML 导入/导出也处理分类默认值或分类属性。
- 现有设置页可在添加和编辑订阅时选择内容类型；主页添加入口在下一阶段接入。
- 在隔离资料中从设置页实际添加四条源，分别选为图片、视频、文章、社交，共入库 178 条。图片与视频样本均有封面；微博热点样本没有作者或媒体，不能代表完整社交帖子。
- 另建旧版 v3 源库和 v1 条目库，各放入一条记录；启动新版应用后升级为 v4/v2，原订阅与文章仍在，分别获得 `articles` 和 `{}` 默认值。测试资料没有写入日常应用目录。

## 第二阶段界面验证记录

- 订阅栏已从遮挡正文的弹出菜单改为工作区常驻列。五个内容类型在订阅栏顶部横向切换，订阅源列表按类别过滤，原有分组在类别内显示。主页加号打开 URL 和类别表单，可直接添加真实 RSSHub 源。
- 「全部」与「文章」共用列表和阅读区，中间仅保留可拖动的分隔线。列表宽度可用左右方向键调整并保存在本地；窄窗口限制列表上限，为阅读区留出空间。社交、图片和视频分别使用时间线、图片网格与视频封面布局。
- 原窗口顶部的刷新、全部已读、通知和设置操作移至底部状态栏，窗口最小化/最大化/关闭仍位于右上角。F1 聚焦订阅列表，F8 聚焦分类标签，方向键可切换分类。
- 在隔离的 Electron 数据目录中，通过**主页加号**分别添加掘金、微博热点、Bing、B 站四个 `http://localhost:1200` 源。样本分别显示约 20、50、7、50 条；逐一打开文章、切换分类并拍摄 1440px 截图。程序化拖动使分隔线从 x=668 移至 x=748，订阅栏与内容区边界重合，无重叠。
- 在最小 992px 宽度复查：页面没有横向溢出，阅读区保留 320px，订阅栏/列表/阅读区及底部状态栏边界分别对齐；深色主题下也检查了同一布局。
- 隔离测试截图可直接检查：[文章三栏](previews/articles.png)、[社交时间线](previews/social.png)、[图片流](previews/pictures.png)、[视频流](previews/videos.png)、[992px 深色布局](previews/dark-992.png)。截图中的文章和封面来自本地 RSSHub 当前响应，仅用于视觉验收。
- 微博热点只提供短标题，没有发布者、正文和图片，因此目前只能验证社交时间线的缺字段回退。进一步打磨社交卡片前应换用内容完整、可稳定访问的真实社交源。侧栏宽度调整、设置布局、隐私模式和更严格的视觉细节对齐仍在后续阶段。

## 第三阶段窗口与图片流修正

- 对照用户提供的 Folo 图片页截图，确认先前的视觉差异来自渲染层：原有 Windows 窗口本身已使用无边框 Electron 窗口，但额外渲染的全宽顶部导航栏让界面看起来像传统窗口。现在工作区和订阅栏从窗口顶端开始，窗口按钮单独位于右上角；移除了顶部导航、分类下方、列表标题以及底部状态区不必要的横向边线。列表/阅读区之间仍保留可拖动的**竖向**分割线。
- 订阅栏顶部改为品牌区和操作按钮，五分类改为横排图标及未读数；图片流选中订阅后，在内容标题展示订阅名称与图标。图片卡片改为无外框的正方形封面，标题和来源排列在图片下方。
- 用主页加号实际添加 `http://localhost:1200/bing`，选中该图片源后截图验收。1440px 宽度下工作区与订阅栏顶端均为 `y=0`，窗口按钮只占右上角 144px；首张封面为 255.5px 正方形，7 张远端图片加载后均显示。另用四类 RSSHub 数据重拍文章、社交、视频和 992px 深色界面；最小宽度没有横向溢出。

## 第四阶段设置页与隐私模式

- 参考 Folo 设置页截图，将原顶部横排选项改为居中的双列设置面板：左侧固定分类导航，右侧独立滚动，阅读界面留在半透明遮罩后方；保留订阅源、分组、规则、服务、应用偏好与关于入口。应用偏好按应用程序、订阅、其他分段，常用设置的说明在左、控件在右。Esc 和右上角按钮仍可退出；上下方向键可切换设置分类。
- 订阅源库升至 v5，新增持久化的 `private` 标记，旧库与旧备份默认 `false`。在订阅源设置中选择具体订阅后，可将其标记为私密。应用偏好中的“隐藏私密订阅”开关保存在本地应用设置中；开启后过滤侧栏、分类计数、文章列表及社交/图片/视频流，并避免打开隐藏文章、通知泄露和“全部标为已读”误处理私密订阅。该开关仅影响本机显示，不删除或加密数据。
- 使用隔离的 Electron 资料，通过主页添加 `http://localhost:1200/bing`：开启前图片流显示 7 项；标记该订阅私密并开启模式后，侧栏只剩“全部文章”，列表中无该源条目；页面重载后开关仍开启；关闭后该源与 7 项条目恢复。1440px 浅色与 992px 深色设置页均无横向溢出。预览：[设置页](previews/settings.png)、[992px 深色设置页](previews/settings-dark-992.png)。

## 第五阶段分栏与工具栏修正

- 文章列表与阅读区的分隔器保留 9px 命中区域，但只绘制 1px 竖线。拖动改用 Pointer Events、指针捕获与拖动遮罩；在松开、指针取消、窗口失焦和组件卸载时结束拖动。窗口缩窄时暂时压缩列表宽度，恢复窗口后优先恢复用户保存的宽度。
- 刷新、仅未读和全部标为已读操作移到条目列表标题栏；社交、图片、视频的同组操作放到内容标题栏。嵌入式阅读区使用自己的头部，不再带弹窗的左右占位和关闭按钮；窗口控制按钮仍单独位于最右上角。明确了媒体页顶端、阅读区顶端和空阅读区的窗口拖动区域。
- 删除分类与缺少网站图标的订阅源前面的占位方框。图片和视频网格由可用宽度决定列数，视频封面保持 16:9。
- 在隔离的 Electron 资料中从 `http://localhost:1200/nasa/apod` 加入真实图片订阅。992/1200/1440/1920px 宽度下图片列数分别为 1/2/3/4；1200px 三栏中，分隔线绘制宽度为 1px，列表可从 390px 拖到 464px。打开含网页内容的文章后又从 464px 拖回 410px；两次松开后继续移动鼠标，列表宽度均保持不变。浏览器图片完整加载后检查了网格截图。
